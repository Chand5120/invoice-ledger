# Invoice Ledger

A fully self-contained Invoice Ledger implementation using dbt, FastAPI, and React + TypeScript.

---

## Features

- **Invoice table** — displays all invoices with client, amount, status, risk tier, and days overdue
- **Summary cards** — total invoices, total amount, outstanding, collected, overdue count, high risk count
- **Filters** — filter by status (paid / pending / overdue), risk tier, and client name (debounced search)
- **Risk classification** — automatically classifies overdue invoices as LOW / MEDIUM / HIGH based on days overdue
- **Ledger status** — SETTLED / OUTSTANDING / DELINQUENT derived from invoice status
- **Strict type safety** — TypeScript frontend types mirror Pydantic backend models exactly

```

      │
      ▼
┌─────────────┐
│   Staging   │  stg_invoices           — type casting, cleaning, normalisation
└──────┬──────┘
       │
       ▼
┌──────────────┐
│ Intermediate │  int_invoices_enriched  — business logic, derived fields
└──────┬───────┘
       │
       ▼
┌──────────────┐
│    Marts     │  mart_invoice_ledger    — final query-ready table (materialized)
└──────┬───────┘
       │
       ▼
┌──────────────┐
│   FastAPI    │  /api/v1/invoices       — strict Pydantic response contract
└──────┬───────┘
       │
       ▼
┌──────────────┐
│    React     │  InvoiceLedger          — TypeScript types mirror Pydantic models
└──────────────┘
```

## Key Design Decisions

### Mock Data
The mock invoice data in `data/seeds/raw_invoices.csv` was generated with the assistance of Claude (Anthropic) to cover a realistic spread of invoice statuses, risk tiers, clients, and date ranges.

### Why DuckDB?
DuckDB is an embedded analytical database — no server needed, single file, fast SQL. Ideal for a local data stack. The dbt mart is materialized as a table inside `backend/invoice_ledger.duckdb` (generated at runtime, not committed to the repo).

### Why three dbt layers?
Each layer has a single responsibility:
- **Staging** — raw data only. No business logic. Cast types, normalize casing, handle nulls.
- **Intermediate** — business logic only. Derived fields: `days_overdue`, `is_paid`, `outstanding_amount`, `risk_tier`.
- **Marts** — presentation layer. Final fields consumed by the API. Materialized as a `TABLE` for fast reads.

### Why `TABLE` materialization for marts only?
Staging and Intermediate are `VIEW` — they recompute on demand and stay lightweight. The mart is `TABLE` — it persists the result so the API reads pre-computed data without re-running transformations on every request.

### Pydantic + TypeScript contract
The TypeScript `Invoice` interface in `frontend/src/types/index.ts` mirrors the `InvoiceResponse` Pydantic model exactly. Any contract mismatch surfaces immediately as a TypeScript error — no silent runtime failures.

### Idempotency
- `dbt seed --full-refresh` is idempotent — running it multiple times produces the same result.
- `dbt run` rebuilds models from scratch — running it again produces the same mart.
- The FastAPI layer is read-only — no mutations, no side effects.

### Avoiding hidden side effects
- The API connects to DuckDB in **read-only mode** — no accidental writes.
- CORS is restricted to `localhost:5173` — no unintended cross-origin access.
- All filters use parameterized queries — no SQL injection risk.
- The dbt profile writes the DuckDB file to a single known location (`backend/invoice_ledger.duckdb`) — no hidden file creation.

## Running Locally

### Prerequisites
- Python 3.11+
- Node.js 20+
- pip

### One-command setup
```bash
bash setup.sh
```

### Manual setup

**1. Run dbt (data layer)**
```bash
pip install dbt-duckdb
cd data
dbt seed --profiles-dir . --full-refresh
dbt run --profiles-dir .
cd ..
```

**2. Start the backend** (Terminal 1)
```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload
```

**3. Start the frontend** (Terminal 2)
```bash
cd frontend
npm install
npm run dev
```

### URLs
| Service | URL |
|---|---|
| Frontend | http://localhost:5173 |
| API | http://localhost:8000 |
| API Docs (Swagger) | http://localhost:8000/docs |

> **Note:** The `backend/invoice_ledger.duckdb` file is generated by dbt at setup time and is not committed to the repository.

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/v1/invoices` | List all invoices with summary |
| GET | `/api/v1/invoices?status=overdue` | Filter by status |
| GET | `/api/v1/invoices?risk_tier=HIGH` | Filter by risk tier |
| GET | `/api/v1/invoices?client_name=acme` | Filter by client name |
| GET | `/api/v1/invoices/{id}` | Get single invoice by ID |
| GET | `/health` | Health check |

## Layer Communication

```
dbt seed     → loads raw_invoices.csv into DuckDB
dbt run      → transforms data through 3 layers → writes mart_invoice_ledger table
FastAPI      → connects to invoice_ledger.duckdb (read-only) → queries mart
React        → fetches /api/v1/invoices → renders InvoiceLedger component
```
